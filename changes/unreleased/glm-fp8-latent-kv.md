## New features and improvements

- GLM can keep its MLA latent cache in fp8 (`--kv-dtype fp8`, or `REXL3_GLM_KV=fp8`). Each token's 512 latent values per MLA layer are stored as E4M3 with one fp32 scale (`amax / 448`, round to nearest even, saturating): 516 bytes instead of 1,024. With the pooled indexer keys, which stay fp16, that is 6,380 bytes a token instead of 11,968, so the planner fits about 1.9 times the tokens in the same memory. The latent write quantises each row once. Every attention kernel (decode, verify, sparse, head-split, the prefill slab) dequantises into the tiles the fp16 kernels use, so outputs match fp16 attention over the dequantised cache bit for bit. Drafted, concurrent and prefix-restored runs read the same quantised bytes, so they stay exact. fp16 remains the default. Both TP ranks must use the same format: the Hello compares it, and the system fingerprint (`_glmkv8`) and the prefix namespace both record it.
